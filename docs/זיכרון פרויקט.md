## החזון בקצרה
משרד תיווך שבו **AI עושה את העבודה האלגוריתמית**, ו**אדם עושה את העבודה הפיזית והאנושית**. המוצר מיועד ל**מתווך סוליסט**. כל מתווך הוא חשבון נפרד, ומבנה ה-SaaS נשמר, אבל אין משרדים עם כמה משתמשים.

## Workflow (הוחלט)
**צד המוכר:**
1. Sourcing (AI): מודעות פרטיות, רשימות, הפניות ומאגרים חיצוניים.
2. **אישור קמפיין ע"י המתווך** (שער אנושי).
3. Outreach (AI): וואטסאפ, ואחרי הסכמה **שיחת Voice AI** (כבר ב-MVP) כדי לקבוע פגישה.
4. Scheduling (AI): קביעת פגישה לפי כללי הזמינות של המתווך.
5. פגישת גיוס (אדם), ואז דיווח תוצאה:
   - **גויס** ← הזנת הנכס ← שיווק.
   - **לא גויס** ← Follow-up (AI) לפי תוכנית המתווך, או **סגירת חיזורים**.

**צד הקונה:**
6. שיחות נכנסות: **המתווך עונה**, דרך **מספר וירטואלי** עם הקלטה ותמלול.
7. Call Intelligence (AI): חילוץ פרופיל קונה ← CRM.
8. לופ קונה (AI): התאמות בתוך המאגר ומחוצה לו ← שליחה בוואטסאפ ← התכתבות ← תיאום סיור.
9. סיור (אדם):
   - **מעוניין** ← הצעה ← משא ומתן. **המתווך מוביל, וה-AI מסייע** (Deal Assist).
   - **לא מעוניין** ← חזרה ללופ.
10. הלופ נעצר רק ב-**opt-out של הקונה** או **כשהמתווך עוצר**.

## רשת שיתופי פעולה: מחלקה 9 (⏸ נדחתה להמשך ב-21.10. נשמר לעתיד)
- **נכנס:** הסוכן שואב נכסים מ**קבוצות וואטסאפ שהמתווך בחר מראש**, מסווג, מחלץ פרטי נכס ומתווך, ומסיר כפילויות. הנכס נשמר כ"נכס שת"פ חיצוני" **רק במשרד ששאב אותו**, ומחפשים לו התאמות.
- **יוצא (רשת):** נכס שלנו שנפתח לשת"פ נכנס אוטומטית ל**כל משרדי METATRON**, עם **פרטי המתווך המטפל בלבד**. פרטי המוכר מוסתרים תמיד.
- **יוצא (קבוצות):** לכל נכס המתווך בוחר **אוטומטי** (פעם ביום או לפי הגדרה) או **ידני**. לנכסים הידניים המערכת **ממליצה כל כמה ימים**. אפשר להחליף מצב בכל רגע.
- **חיבור לוואטסאפ, כל מתווך בוחר:**
  - **מכשיר מקושר** (WhatsApp Web/Baileys): אוטומטי, לא רשמי, סיכון חסימה.
  - **האזנה להתראות באנדרואיד:** קריאה בלבד.
  - **העברה לבוט** (Cloud API): עובד גם באייפון.
  - הסיבה: ה-Cloud API הרשמי לא תומך בקבוצות קיימות.
- **תכנון טכני:**
  - `network/collab_listings` גלובלי, בהטלה מנכס המשרד ובלי שדות מוכר.
  - `property.collab{…}`
  - WA Gateway (Node + Baileys)
  - Notification Listener ב-nadlan-pro
  - Crews: Collab Ingestion ו-Collab Publisher
  - Matching על שלושה מאגרים
  - בונים על ה-collab הקיים ב-nadlan-pro.

## Roadmap לסוליסט (הוחלט 20.10.2026)
1. **פנייה ראשונה בוואטסאפ** למוכרים.
2. **שיחה טלפונית** (Voice AI) אחרי הסכמה, כדי לקבוע פגישת גיוס. התיאום ביומן נכלל בשלב הזה.
3. **פרסום ו-CRM**: קליטת הנכס שגויס ופרסום בערוצים.
4. **ניתוח שיחות, חיפוש והתאמות**: תמלול שיחות נכנסות ← פרופיל קונה ← התאמות.
5. **Follow-up** למוכרים שלא גויסו, לפי הגדרות שהמתווך קובע.

## סטאק
- **הוחלט:** Backend ב-Python, סוכנים ב-CrewAI, אפליקציית מתווך `nadlan-pro` (React Native + Firebase), Firestore כמקור האמת ל-CRM, שילוב ספקי LLM (Opus לתזמור, Sonnet לשיחה ותוכן, Haiku לסיווג).
- **הצעות שעוד לא אושרו:** FastAPI, Redis Streams כ-Event Bus, arq/Celery, Postgres + pgvector, Playwright.

## הקשר טכני: nadlan-pro (נבדק ב-18.10.2026)
- **Firestore:** `users/{uid}/{properties,clients,tasks,propertyImages,propertyPdfs,agent_conversations}`, ובנוסף `agents/{uid}`, `posts`, `phones`.
- **אין multi-tenancy.** המשרד מופיע רק כטקסט בפרופיל.
- **Cloudflare Worker** (`worker/`): דפי שיתוף, SMS (InforU), Twilio OTP, סוכן וואטסאפ (`wa.js`, Meta Cloud API + Haiku), KV לתמונות.
- **התאמות:** `src/utils/matching.ts`.
- **אנדרואיד:** פלאגינים ל-call-log ולמודל שמופיע בשיחה נכנסת.
- ⚠ **מפתח Anthropic חשוף** ב-`app/property/from-text.tsx` (`EXPO_PUBLIC_ANTHROPIC_KEY`). צריך לתקן בשלב 0.
- **fb-poster:** Express + Puppeteer + SQLite, פרסום לקבוצות פייסבוק.
