חזון ועקרונות

מה אנחנו בונים ולמה
✓ הוחלט
במשפט אחד: פלטפורמת SaaS שהופכת כל משרד תיווך, מסוליסט ועד משרד עם צוות, ל"משרד מוגבר". צוות סוכני AI עושה את כל העבודה החוזרת והאלגוריתמית, והמתווכים מתפנים לעבודה שרק בני אדם יכולים לעשות.

🤖 מה עושים סוכני ה-AI

  • מאתרים מוכרים פוטנציאליים, ממודעות פרטיות, רשימות ומאגרים
  • פונים בוואטסאפ ובשיחה קולית כדי לקבוע פגישת גיוס
  • מתאמים פגישות וסיורים לפי היומן והכללים של המתווך
  • עושים Follow-up למוכרים שלא גויסו
  • מפרסמים נכסים בכל הערוצים ומודדים ביצועים
  • מתמללים שיחות ובונים פרופיל קונה ב-CRM
  • מחפשים התאמות בתוך המאגר ומחוצה לו ומנהלים את הלופ מול הקונה
  • מסייעים במשא ומתן: הצעות, עסקאות השוואה וטיוטות
  • סוכן-על מפקח על הכל: SLA, תקיעות ודוחות

👤 מה עושים המתווכים

  • מאשרים קמפיין פנייה לפני שיוצאת פנייה כלשהי
  • נפגשים עם המוכר ומגייסים את הנכס
  • מזינים את פרטי הנכס דרך האפליקציה
  • עונים לשיחות נכנסות מקונים (השיחות מוקלטות ומתומללות)
  • מציגים נכסים בסיורים
  • מדווחים תוצאה של כל פגישה וסיור
  • מובילים את המשא ומתן וסוגרים עסקה
  • מגדירים לסוכנים כללים: זמינות, תוכנית Follow-up ותסריטים

עקרונות יסוד

Human-in-the-loop
אין פנייה יוצאת בלי אישור. דיווח של המתווך הוא שער המעבר בין שלבים. מחירים והתחייבויות קובע רק אדם.
מתווך סוליסט
כל מתווך הוא חשבון נפרד עם הנתונים שלו. אין משרדים מרובי משתמשים ואין היררכיה.
הסוכן רואה רק את החשבון שלו
כל סוכן AI פועל בשם המתווך, ואין לו גישה לנתונים של מתווכים אחרים במערכת.
Opt-out גלובלי
כשאיש קשר מבקש "תפסיקו", כל המחלקות מפסיקות לפנות אליו מיד.
Adapter לכל ערוץ
ערוץ פרסום או תקשורת חדש מתווסף כ-adapter, בלי לגעת בסוכנים.
Audit מלא
כל פעולה של סוכן נרשמת: מה עשה, בשם מי, ומתי.

מתווך סוליסט: נתונים ואבטחה

המוצר מיועד למתווך שעובד לבד. כל מתווך הוא חשבון נפרד
✓ הוחלט 20.10
שינוי היקף: ירדו סוגי המשרדים, ההבחנה בין מנהל למתווכים, טבלת ההרשאות ושיתוף בין מתווכים. מבנה ה-SaaS נשאר, כי כל מתווך נרשם כחשבון נפרד, אבל בתוך החשבון יש משתמש אחד בלבד.

מה זה מפשט

  • הנתונים נשארים תחת users/{uid}, בדיוק כמו היום ב-nadlan-pro
  • אין צורך בהגירה למבנה חדש של משרדים
  • אין טבלת הרשאות: המתווך רואה את כל מה ששלו
  • אין בקשות שיתוף ואין התאמות בין מתווכים
  • פחות קוד, פחות טסטים, ופיתוח מהיר יותר של ה-MVP

🛡 מה נשאר באבטחה

  • לסוכני LLM אין גישה ישירה ל-DB. כל פעולה עוברת דרך Repository שמסנן לפי ה-uid של המתווך.
  • Firestore Security Rules: רק הבעלים קורא וכותב, כמו היום.
  • כל פעולה של סוכן נרשמת ב-agent_runs.
  • סודות ומפתחות API רק בצד השרת. בהתאם לכך מתקנים את המפתח החשוף ב-nadlan-pro.

מבנה הנתונים ● הצעה טכנית

users/{uid} ├─ properties/ ← existing ├─ clients/ ← existing (buyers) ├─ tasks/ ← existing (calendar) ├─ agent_conversations/ ← existing (WhatsApp) ├─ sellers_pipeline/ ← new: sourced sellers + state ├─ buyer_loops/ ← new ├─ calls/ ← new: recordings, transcripts ├─ deals/ ← new: offers, commission ├─ agent_runs/ ← new: audit of AI actions └─ settings/ ← new: availability, follow-up plan, virtual number, scripts
